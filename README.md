# Shift_App

アルバイトのシフト希望の提出・シフト作成・公開をオンラインでまとめて行うためのアプリです。

## 解決したいこと

いまのシフト運用はこんな流れになっています。

- シフト希望はLINEで個別に集めていて、書き方が人によってバラバラ
  - 「カレンダーの行ける日に○、時間を書く」型
  - 「●を付けた日のうち週3日以上、17時から」型 など
- 集めた希望を手作業で紙にまとめてシフトを作成し、店長が最終チェック
- 完成したシフトは写真で共有されるため、あとから更新されても最新版は店に行かないと確認できない

このアプリでは、**スタッフが提出した希望がそのままデータベースに入り、作成したシフトはいつでも最新版を見られる**状態を目指します。

## 使う人と役割

| 役割 | やること |
| --- | --- |
| スタッフ（10〜15名） | LINEから希望を提出する／確定シフトを見る |
| シフト作成担当 | 全員の希望を一覧で見ながらシフトを組む |
| 店長 | 作成されたシフトを最終チェックして公開する |

## 提出期限

- 毎月15日 23:59（日本時間）が、翌月分の提出期限（例：12月分は11月15日まで）
- 期限までは、提出後に「内容を修正する」から直せる
- 期限を過ぎると直接は変えられず、「変更を申請する」から作成担当に申請する
- 作成担当（管理用の合言葉）は期限後でも直接修正できる
- 期限の判定はサーバー側でも行う

## 希望データの形

提出方法に関係なく、希望は次の形で保存します。

- 日ごとの可否：○（入れる・時間指定）／△（相談可）／×
- 希望日数：週◯日以上・最大◯日
- 時間のデフォルト（例：17時〜）
- 備考（自由記述）

## 開発の順番

1. LINE公式アカウント ＋ カレンダー形式の提出画面 → データベースに保存
2. 希望の一覧表 ＋ シフト作成画面（作成担当用）
3. シフト公開ページ ＋ LINEでの更新通知
4. （検討中）文章で送られた希望をAIで読み取る
5. 自動でシフトの下書きを作る機能

## 方針

- **0円で作る**：無料で使えるサービスの範囲だけで構成する
- **データはリポジトリに入れない**：スタッフの名前・希望・シフトなどはデータベース側に置く
- **秘密情報はコミットしない**：LINEのアクセストークンやAPIキーは環境変数などで管理する

## 技術構成

- 画面：HTML / CSS / JavaScript（フレームワークなし）
- サーバー処理：Cloudflare Workers
- データベース：Cloudflare D1（SQLite）
- 公開：GitHubにpushするとCloudflareが自動で公開（Workers Builds）
- 提出の入口：LINE公式アカウント（無料プラン）＋ LINEミニアプリ（LIFF）

## 本人確認のしくみ

- **スタッフ**：LINEの中で提出画面を開くと、LINEが本人を証明するIDトークンを発行する。サーバーはそれをLINEの確認APIに問い合わせてから保存するので、他の人の分を提出・変更することはできない
- **初回だけ名前を選ぶ**：作成担当が登録した名簿から自分の名前を選ぶと、LINEアカウントと結びつく。一度結びついた名前は他のLINEアカウントからは選べない。間違えた場合は一覧画面から作成担当が解除できる
- **作成担当**：一覧画面は管理用の合言葉（`ADMIN_KEY`）で開く

## ファイル構成

```
public/            画面（Cloudflareがそのまま配信する）
  index.html       シフト希望の提出画面（スタッフ用）
  submit.js        提出画面の動き
  admin.html       シフト希望の一覧画面（作成担当用）／ URLは /admin
  admin.js         一覧画面の動き
  common.js        両方の画面で使う共通処理
  style.css        見た目
src/index.js       サーバー処理（/api/〜 へのリクエストを受けてデータベースを読み書きする）
migrations/        データベースのテーブル定義（SQL）
wrangler.jsonc     Cloudflareの設定
```

## セットアップ（Cloudflare）

1. **データベースを作る**：ダッシュボードの「ストレージとデータベース」→「D1」→ 名前 `shift-app-db` で作成
2. **テーブルを作る**：作ったデータベースの「コンソール」に `migrations/` の中のSQLを番号順（0001 → 0002 …）に貼り付けて実行
3. **IDを設定する**：データベースのIDを `wrangler.jsonc` の `database_id` に書く
4. **GitHubとつなぐ**：「Workers & Pages」→「アプリケーションを作成」→ GitHub → このリポジトリを選び、名前を `shift-app` にしてデプロイ
5. **合言葉を設定する**：作成したWorkerの「設定」→「変数とシークレット」に、種類「シークレット」で `ADMIN_KEY`（作成担当用の合言葉）を追加
6. `https://shift-app.<サブドメイン>.workers.dev/` が提出画面、`/admin` が一覧画面

## セットアップ（LINE）

1. LINE公式アカウントを作る（無料のコミュニケーションプラン）
2. LINE Developersコンソールでプロバイダーを作り、チャネルの種類「LINEミニアプリ」でチャネルを作る
3. エンドポイントURLに提出画面のURL（`https://shift-app.<サブドメイン>.workers.dev/`）を設定し、スコープは `openid` と `profile`
4. LIFF IDとチャネルIDを `wrangler.jsonc` の `vars` に書く
5. LINE公式アカウントのリッチメニューに、ミニアプリのURLを開くボタンを置く

## 提出のお願い（LINEでの自動リマインド）

- 毎日12:00（日本時間）にCloudflareの定期実行（Cron Trigger）が動き、12日（締切3日前）と14日（前日）なら、翌月分を**まだ提出していないLINE連携済みの人だけ**にLINEで送る
- 同じ月・同じ種類は1回だけ（送信記録 `reminder_log` で二重送信を防ぐ）
- 一覧画面から「未提出の人に今すぐ送る」もできる
- 設定：LINE Official Account Managerで Messaging API を有効にし（プロバイダーはミニアプリと同じものを選ぶ）、LINE Developersで長期のチャネルアクセストークンを発行して、Cloudflareのシークレット `LINE_MESSAGING_TOKEN` に入れる

## 手元で動かす場合

```
npm install
echo "ADMIN_KEY=test-admin" > .dev.vars
npm run db:init:local
npm run dev
```
